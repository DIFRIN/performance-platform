# ADR-047 - Optional transport mTLS and independent web HTTPS

## Status

Accepted: scope and listener isolation confirmed by the user.

## Context

HTTP, Kafka, RabbitMQ and TCP Socket transport need optional mutual TLS.
The browser-facing UI/API must support one-way HTTPS without requesting agent
certificates. AGENT remains `WebApplicationType.NONE` (ADR-019).

## Decision

- Resolve `transport.tls.bundle` through Spring Boot `SslBundles` only when
  `transport.tls.enabled=true`. PEM, JKS and PKCS12 are supported by Boot.
  Disabled transport TLS preserves plaintext defaults.
- Require an explicit CA/truststore. `transport.tls.client-auth=NEED` is the
  default; it additionally requires a certificate/private key. `NONE` permits
  one-way transport TLS where the remote server policy permits it.
- Keep hostname verification enabled on every outbound connection. Apply bundle
  protocols/ciphers. Reject invalid configuration; never downgrade or trust all.
- HTTP uses a dedicated JDK HTTP(S) listener (default port 8091), not MVC or the
  UI connector. `connect()` starts it before agent registration. AGENT accepts
  tasks/signals; ORCHESTRATOR accepts execution/lifecycle events. Callback URLs
  are advertised by bootstrap composition, not inferred by the execution engine.
  Outbound and inbound HTTP share the transport bundle, never the web bundle.
- Socket uses SSL sockets on initial connection and reconnect. A TLS handshake
  completes before server connection registration, with bounded handshake timeout
  and virtual-thread isolation. TLS requires an explicit runtime role.
- Kafka producer and consumer factories both use a bundle-backed Kafka
  `SslEngineFactory`. Broker mTLS enforcement remains broker configuration.
  RabbitMQ uses the bundle SSL context and mandatory hostname verification;
  broker client-certificate enforcement is configured separately.
- UI/API use standard `server.ssl.bundle` and `server.ssl.client-auth=NONE`.
  Existing OAuth2/JWT authorization is unchanged. No UI connector exists on AGENT.
- No global JVM SSL properties, core contract changes, SUT client changes or new
  Maven dependencies. Only transport adapters and bootstrap composition change.

## Consequences

- HTTP becomes a real bidirectional distributed transport rather than local
  event callbacks plus outbound task POSTs. Old direct-construction plaintext
  fixtures remain supported without creating a listener.
- HTTP callback base path must be identical on orchestrator and agents.
  Agent advertised URLs must be reachable from the orchestrator and covered by
  certificate SANs. The orchestrator URL excludes the callback base path.
- HTTP rejects unaccepted commands explicitly instead of logging successful
  dispatch after failed POSTs. Received requests are limited to 16 MiB.
- Certificates establish membership of a trusted CA, not application-level
  permissions or binding between certificate subject and reported agent ID.
  Use a dedicated transport CA and network access controls.
- Certificate renewal requires restarting affected processes. Live bundle
  refresh is not implemented.
- Test-only certificates are generated by OpenSSL, never committed, and expire
  after seven days. Production certificates/private keys remain operator-managed.
